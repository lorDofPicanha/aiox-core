01 · Tese

Por que organização e não coleção de prompts.

A diferença entre um sistema de agentes que funciona e um que vira teatro está em três coisas: autoridade exclusiva, gate material e roteamento determinístico. O AIOS tem as três escritas em arquivo, não em intenção.

Autoridade exclusiva
Ninguém faz o trabalho do outro

Só @devops dá git push. Só @architect decide arquitetura. Só @qa emite veredito. Está no Art. II da Constituição — não é convenção, é lei do sistema.

Gate material
Burocracia só quando dói

Gate dispara por gatilho material — DDL em SQL, criação de agente-pessoa, merge. Nunca em toda tarefa. Anti-burocracia é princípio declarado da policy de roteamento.

Roteamento determinístico
Consulta é exceção, não regra

Intenção → domínio → squad → chief, por tabela. O Expert Pool (186 consultivos) só é chamado sob incerteza ou risco. Council só em escalação.

Princípio-raiz

CLI First (Art. I, NON-NEGOTIABLE). Toda funcionalidade precisa funcionar 100% via CLI antes de existir UI. Dashboards observam, nunca controlam. A hierarquia é CLI → Observability → UI. Isso explica por que quase tudo no AIOS é um .js chamável por node, e por que a ponte entre CLIs é subprocess + arquivo compartilhado, não MCP.

07 · Mind clones

253 mentes indexadas — e o que de fato são.

Um mind clone não é um modelo fine-tunado nem uma API externa. É um arquivo markdown denso com Voice DNA (como a pessoa fala) e Thinking DNA (como a pessoa decide): frameworks nomeados, modelos mentais, comandos, quando usar e — crucialmente — quando não usar. O motor lê esse arquivo, extrai as seções relevantes e devolve contexto estruturado para o agente chamador responder na perspectiva daquele expert.

Gate de DNA — bloqueia de verdade

Criar um novo agente-pessoa em squads/*/agents/ exige DNA extraído. O hook mind-clone-governance.py retorna exit 2 (BLOCK) se você tentar criar um clone nomeado sem o DNA — ou usar sufixo funcional para disfarçar. Ativo desde 22/Mai/2026. É a defesa contra "canalizar um expert pelo nome" sem substância — o antipadrão que produz conselho genérico com etiqueta de celebridade.

Regra de quando consultar

Consultar antes de finalizar: criação de story/PRD, arquitetura, pricing, segurança, fluxo de UX, schema de DB, decisão jurídica/regulatória, decisão de mercado, ou qualquer escolha estratégica/irreversível.

PASSO 3

Por política, independentemente da rota escolhida.

Executive Council só em tradeoff cross-squad, exceção de política ou decisão estratégica.

Art. VII — a economia por trás da regra

Anúncio Anthropic de 14/Mai/2026, vigente 15/Jun/2026: a subscription se dividiu em dois pools. (1) Interativo — Claude.ai e Claude Code no terminal/IDE = inalterado. (2) Programático — claude -p, Agent SDK, GitHub Actions, subprocess automatizado = pool metered separado, a preços de API cheios, sem rollover.

Consequência de arquitetura: Claude interativo é a superfície de raciocínio (barata, preferida para decisão delicada) e Codex/Gemini são as superfícies de volume. O delegate.js avisa ao usar --to claude e sugere alternativa — mas não bloqueia, porque há casos legítimos.

Por que subprocess e não MCP

Decisão registrada no cabeçalho do delegate.js: "MCP handshakes são frágeis — falham em Antigravity, dão version mismatch em Codex". A ponte usa subprocess simples + arquivos compartilhados, o que funciona em toda IDE que tenha terminal, com zero risco de handshake. MCP é usado como conveniência, nunca como caminho crítico.

Modo heurístico — sem chave de API

O HYDRA roda o pipeline ponta a ponta sem nenhum LLM: scoring e extração determinísticos, zero chamada de rede além dos fetchers de RSS/GitHub, custo zero. Serve para emergência de quota, ambiente air-gapped, CI/smoke test e modo contínuo barato. O modo LLM fica para o primeiro passe em domínio novo e para fontes de alto sinal — onde a extração sutil (citações, nomes de framework, opinião) vale o custo.

Leitura honesta

A espinha do AIOS — constituição, autoridade exclusiva, roteamento determinístico, delegação multi-CLI — está escrita, implementada e em uso. O que está frouxo é a camada de enforcement automático: quase tudo que deveria bloquear apenas registra. Na prática o sistema funciona porque o operador L5 segura a disciplina — o que é sustentável em escala de um founder, e quebra no dia em que virar escala de time. As duas alavancas de maior retorno hoje: (1) re-sincronizar o registry IDS e colocá-lo em rotina de commit; (2) ligar corporation.permissions.enforce e ver o que quebra.
