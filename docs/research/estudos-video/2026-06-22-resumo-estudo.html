Parte 1 · Marketing

Curso de Marketing do Dener Lippert

Fundador da V4 Company · canal Staage · curso de 9h já vendido por +R$1.500

TL;DR. Marketing é ciência, não arte. Só é marketing quando vende (mais gente, mais vezes, maior valor). Valide o produto antes de tudo, decida por teste (1 variável isolada), priorize canais por atenção×intenção, faça loop de growth, construa oferta com mecanismo único + inversão de risco, e ganhe no LTV via atendimento e retenção — não no múltiplo de ROI.

1.1Fundamentos — a mentalidade

  • Definição operacional: marketing só conta quando vende — o produto, para mais pessoas, mais vezes, pelo maior valor.
  • Cientista, não advogado: decida por dado, refute as próprias hipóteses; toda verdade é transitória. Intuição gera hipótese, nunca decide.
  • Método científico (5 passos): Observar → Problematizar (tese/antítese/síntese) → Hipótese → Testar isolando 1 variável (amostra significativa) → Concluir.
  • Lei base: nenhum marketing, verba ou time de vendas vende produto ruim → validar PMF antes do planejamento.

1.2Estratégia — onde jogar

  • Os 4 fits: Produto ↔ Mercado ↔ Modelo de monetização ↔ Canal. Mudar um quebra a tração.
  • Matriz de Inovação (Indústria/Serviço/Varejo × On/Off): mapeie onde está, expanda pros outros quadrantes pra multiplicar receita.
  • 5 Níveis de Consciência (Schwartz): inconsciente → problema → solução → produto → vendedor. Baixa consciência ⇒ investir em aquisição/educação; alta ⇒ pode monetizar direto.
  • Persona: 2–4 variações (nunca 1, pra testar). Mapear dores (dinheiro/amor/reconhecimento/segurança), transformações (A→B) e objeções (preço/confiança/tempo/"funciona pra mim?").

1.3Os 4 Pilares + maturidade

  • 4 Pilares (Método V4): Tráfego → Engajamento → Conversão → Retenção. Conversão é a interseção dos 4 (não-linear). Analogia loja física: ponto / vitrine / pagamento / cartão-fidelidade.
  • Steps V1–V4: V1 descobrir indicadores → V2 maturar (concentra budget nas ~3 vencedoras) → V3 escalar → V4 profissionalizar (divisão do trabalho). Não prometa ROI em V1/V2.
  • Loop de growth: reinvestir receita no próprio canal = crescimento exponencial/previsível, vs. linear (PR/loja) que não reinveste no mesmo ponto.

1.4Canais & Tráfego

  • 2 eixos pra escolher canal: Atenção × Intenção (quer alta nos dois) · Necessidade × Desejo (necessidade → Google Search; desejo → descoberta/social).
  • Meça ANTES de rodar (6 formas): pixel+UTM · CRM · correlação (TAM por bairro IBGE×ticket) · mecânica (0800/URL exclusiva) · conversão offline (match de base). "Se não souber mensurar, vai dar merda."
  • Conteúdo define audiência: o criativo filtra quem clica antes do targeting.
  • Grid de Públicos (Digital Marketer): públicos × argumentos; veicula tudo, mantém vencedores, gera novos argumentos deles. 3–4 × 3–4 por rodada.
  • Aquisição antes de Monetização: amplo (vídeo) → retargeting de quem viu ≥75% → página de venda. "A panela pega no aquário, não no oceano — aumente o aquário."

1.5Google Ads — específico

  • Correspondências: Ampla (descobrir termos) · Frase " " · Exata [ ] · Inteligente (só alta intenção). Use termos de pesquisa reais pra negativar e achar contextos novos.
  • Branded vs core: separe rigorosamente — misturar infla CTR/conversão e engana a leitura. "Tudo que é marca deixa na marca; tudo que é core no core."
  • Concorrente: lance na palavra OK; nunca o nome no anúncio/página; crie página comparativa (não na home). Nome no anúncio = risco jurídico no BR.

1.6Otimização & Escala

  • Message Match: clicou em A → cai na página A; quebra = bounce/zero conversão. Variação de LP por anúncio, não banner rotativo.
  • 3 alavancas (engenharia reversa): Criativos (comece aqui) → Públicos → Estratégia. Janelas: criativo ~7d, público 7–30d, estratégia 15–30d.
  • 4 passos de escala: 1) mais verba (o passo mais pulado) → 2) mais criativos → 3) mais públicos → 4) mais fontes.
  • Diminishing returns: + verba = + custo por resultado. Gargalo é a página se conversão ~0,x–1%.
  • Fast traffic (mensagem/search-telefone/lead nativo) pra começar e provar; deep traffic (lead+LP/inbound) em paralelo, pronto antes do cliente reclamar.

1.7Oferta & Copy

  • Framework de Oferta: Oportunidade → Persona → Inimigo comum → Promessas → Objeções → Provas → Mecanismo Único → Big Idea. Para cada promessa, uma prova; para cada aumento de consciência, uma quebra de objeção.
  • Mecanismo único (USP): sem ele o produto nunca é campeão. Subniche até virar 1º lugar.
  • Big Idea / Regra de Um: 1 ideia por copy, específica + mensurável + com prazo (ex.: "100 mil em 7 dias").
  • Preço = Oferta − Risco: maximize oferta, minimize risco (garantia/trial/provas/inversão).
  • Jornada do Herói na narrativa → +10–20× alcance no teste de LinkedIn. Transferência de autoridade B2B: podcast com executivos → exibe os logos ("carteiraço").

1.8UX / CRO / Página de Vendas

12 passos do wireframe de Sales Page:

  • Atenção (banner+PUV+message match) → Problema → Agravar → Solução (≠ produto) → Autoridade → Como funciona → Oferta com ganho → Garantia/inversão → Argumentos lógicos → Escassez (stick bar) → Reforço+Medo → Prova social (chave de ouro).
  • CRO (jornada cerebral): Motivação ("vem a mim", 7s) → PUV → Urgência → Mitigar fricção → reduzir incerteza (prova social de gente igual). 1–3 instigam, 4–5 mitigam.
  • 10 premissas da página: objetivo único · CTA único · mobile first (80% do tráfego) · responsiva · rápida · message match · exit popup não invasivo · tags (GA+Pixel+Ads) · Hotjar · testar caminho do usuário.
  • Jobs to be Done: não vende furadeira, vende o furo / o reconhecimento. "Nosso negócio é vender o seu."
  • Emoção: Medo é o mais forte (depois amor, nojo/revolta). Quebra de padrão prende; rosto exagerado converte mais (provado por A/B).

  • Tipos de venda (Winning by Design): Self-service → MLG/inbound (SDR+closer) → SLG/outbound (BDR+closer) → Enterprise. Ciclo: self instantâneo · MLG <10d · SLG 30–60d · Enterprise meses.
  • Lead Response Time: atender em <5 min; conversão despenca a cada 5 min. WhatsApp síncrono: se responde, já liga.
  • Follow-up é o mais crítico: reunião ruim + follow-up bom = venda; reunião ótima + follow-up ruim = venda perdida. Reserve ≥20% do dia (~2h) só pra follow-up; feche toda reunião com próximo passo agendado.
  • ~70% dos leads inbound são ruins → filtro duplo (formulário + SDR) pra não queimar o closer caro.

1.10Métricas, Retenção & Caixa

  • LTV/CAC ideal = 3× (>1 ok · <1 prejuízo · >5 = fora da curva OU investindo pouco). Importa a margem em R$, não o múltiplo. CAC ≈ 70% da margem.
  • Atendimento é lifetime: cai mais por atendimento que por resultado. Evidência de serviço diária ("ligação é prova de amor") — todo dia o cliente pensa em cancelar.
  • RFM (Recência/Frequência/Monetário) → régua por custo: e-mail → remarketing → humano. Cohort por safra e canal (pague mais caro pelo que retém mais).
  • Flywheel de caixa V4: recebe do cliente (~dia 15–20) antes de pagar a mídia (~dia 30).
  • Boi de piranha (isca): margem ~zero ("só pague o frete") atrai volume → upsell/PDV. Gateway com retry recupera 30–40% das recusas.
  • HR Checking (weekly): Resultados (vitórias 1º) → Objetivo SMART → Premissas/Riscos → Entregas por último.
  • CS: NPS (promotores−detratores) · CSAT · MHS ("quão insatisfeito se eu parasse?") — alto MHS = alto LTV e sinal de PMF.

Parte 2 · AI Design

O harness que destrava o Claude Design

Alan Nicolas · Academia Lendária · livestream 1h20

TL;DR. O Claude Design é o melhor motor de design de IA, mas é uma "caixinha fechada" (não instala skills/scripts). Alan descobriu que ele lê obrigatoriamente um CLAUDE.md a cada sessão (herança do Claude Code) e usou isso pra injetar um harness de skills + scripts JS — matando AI slop, garantindo consistência entre 100+ telas e cortando gasto de token.

2.1O hack — passo a passo reproduzível

  • A brecha: Claude Design não instala skills/pacotes pela UI, mas aceita upload de arquivos e lê o CLAUDE.md ao abrir cada sessão.
  • 1. Baixar o ZIP do harness no GitHub (sem instalador — a plataforma bloquearia).
  • 2. Arrastar o .zip pra pasta principal — NÃO clicar "enviar" (gastaria token), só soltar; descompacta em uploads/.
  • 3. Nova conversa: "traga tudo da pasta X pra principal" → usa um move interno (custo mínimo).
  • 4. Novo chat → digitar go → dispara o bootstrap.
  • 5. Truque do marcador: o CLAUDE.md tem um texto-marcador; se ainda não foi alterado, o sistema infere "projeto novo" e roda o setup completo (detecta design system, tokeniza, reescreve bundles, cria componentes JS, estrutura páginas).
  • 6. A parte cara do setup é JavaScript (programado), não deixada "rodando" pela IA → muito menos token.

Skills minúsculas: sem front-matter; chamam internamente as skills nativas do Claude Code/Design → ~600 tokens vs. 2.000–3.000 das originais.

2.3Limitações do Claude Design

  • Caixa fechada: não instala skills/scripts pela UI; sem docs oficiais de customização.
  • Sem npm install: roda servidor Node (Vite/React) mas não instala pacotes.
  • Screenshot = ~20.000 tokens fixos por print (independe da tela); auditorias tiram muitos prints → o harness evita prints, testando via JS.
  • Produz muito AI slop por padrão; não é modular nativamente; acessibilidade nativa fraca.

2.4Boas práticas / economia de token

  • Nova conversa por tarefa.
  • Não use pra TODAS as telas (caro): só telas-chave de referência (home/produto/carrinho/categoria) → delegar o resto ao Claude Code/Codex modular.
  • Resultado: 1 página completa + design system ≈ 7% do limite de 5h.

2.5Por que Claude Design > alternativas

  • Motor da Anthropic é superior (Lovable/Bolt/Canva usam motor por trás); integração navegador+motor dá mais criatividade.
  • Mesmo prompt no Claude Code "puro", Lovable, v0, Grok ou OpenDesign não chega perto.
  • O que faz o design incrível é o harness fechado da Anthropic — o do Alan apenas expande.
  • Enterprise: compartilha design system com o time e replica componentes automaticamente (≠ GitHub). Regra de ouro: nunca duplicar o design system (múltiplas fontes da verdade).

2.6Distribuição & filosofia

  • Repo GitHub open source (alegado "1º harness do mundo pro Claude Design") com docs (runtime/validações/limitações/changelog/CONTRIBUTING), biblioteca de prompts, starters/templates, scripts de tokens.
  • Feedback só via GitHub Issues — loop diário lê issues, corrige e abre PR automático.
  • "Hoje não dou mais prompt, escrevo loopings" — fluxos auto-corretivos; Codex 5.5 high orquestrando Claude Code + Grok + GLM (skill "SellOuter"). GLM/DeepSeek em produção por custo, americanas pra criação.
