## Story

**As a** operadora da ENIAC (Giovanna, fase de busca),
**I want** que o Noyce mostre licitações em um raio de até 500 km da sede da ENIAC (Águas Lindas de Goiás-GO),
**so that** não percamos editais de regiões próximas que hoje ficam invisíveis pelo corte artificial de 170 km, especialmente em estados vizinhos como DF, MG, MT e TO.

## Contexto

Requisito levantado em reunião 15/Jun/2026 (doc 29 §6). O founder afirmou que o raio de 170 km foi limitado "de propósito pra fechar outras coisas" e que vai expandir "um pouquinho". O doc 29 confirma: "confirma o follow-up de raio 500km do doc de discovery."

O código já tem a lógica de haversine e múltiplos níveis de scoring por distância. Em `noyce-capability.ts` a função `distanceScore` já retorna scores para até 500 km (≤100 km → 25, ≤250 km → 20, ≤500 km → 14). Em `noyce-readiness.ts` existe `const near = input.distanceKm <= 170` e `const within = input.distanceKm <= 500`. O hard cutoff de 170 km que bloqueia oportunidades está na lógica de triage.

[AUTO-DECISION] O raio de 500 km é um hard limit ou configurável? → Implementar como constante configurável `MAX_DISCOVERY_RADIUS_KM = 500` em `noyce-source-registry.ts` ou em um arquivo de constantes operacionais. Razão: o founder pode querer ajustar no futuro; configurável evita nova story para mudança de número.

[AUTO-DECISION] A triagem muda com o raio expandido? → Sim. Oportunidades entre 170–500 km que antes eram "Pula" (fora do raio) devem ser reclassificadas como "Olha" (não "Vai") automaticamente, com nota: "Distância [X] km — verificar viabilidade operacional." Razão: distância longa aumenta custo operacional real; "Olha" é o veredicto correto para análise humana, não promoção automática a "Vai".

## Acceptance Criteria

1. **Dado** que o discovery snapshot é construído a partir do PNCP,
   **Quando** o filtro de distância é aplicado,
   **Então** licitações com `distanceKm ≤ 500` são incluídas no snapshot (anteriormente o corte estava em ≤ 170).

2. **Dado** que uma licitação tem `distanceKm` entre 171 km e 500 km,
   **Quando** a triagem `buildTriage` é executada,
   **Então** o veredicto é `"Olha"` (não `"Vai"` nem `"Pula"`) com nota contextual: "Distância [X] km — verificar viabilidade operacional antes de prosseguir."

3. **Dado** que uma licitação tem `distanceKm > 500 km`,
   **Quando** a triagem é executada,
   **Então** o veredicto é `"Pula"` com nota "Fora do raio operacional (> 500 km)."

4. **Dado** que a constante `MAX_DISCOVERY_RADIUS_KM` é alterada (ex.: de 500 para 400),
   **Quando** o discovery é reconstruído,
   **Então** apenas licitações dentro do novo raio são incluídas (configurabilidade verificada por teste).

5. **Dado** que o operador visualiza a lista na aba Mesa ou Monitorar,
   **Quando** há licitações no intervalo 171–500 km,
   **Então** o chip de distância exibe o valor real em km e a tag "Olha" em amarelo (distinguível de "Vai" verde e "Pula" cinza/vermelho).

6. **Dado** que a score de `distanceScore` em `noyce-capability.ts` já tem pesos para faixas até 500 km,
   **Quando** o motor de análise roda para uma licitação entre 171–500 km,
   **Então** o score é calculado corretamente usando a faixa `≤500 km → 14` (sem alteração de lógica existente — apenas a triage muda).

7. **Dado** que todos os testes existentes rodam após a mudança,
   **Quando** `pnpm test` é executado,
   **Então** zero regressões: os testes de triage que assumiam corte em 170 km são atualizados para refletir o novo comportamento.

### Lógica atual de triage (noyce-readiness.ts)

```typescript
// ATUAL:
const near = input.distanceKm <= 170;
const within = input.distanceKm <= 500;
// ... se !near → "Pula" com razão de distância

// NOVO:
const near = input.distanceKm <= 170;          // candidato a "Vai" (sem mudança)
const expanded = input.distanceKm <= MAX_DISCOVERY_RADIUS_KM; // 500 km
// Se near → elegível para "Vai" (como antes)
// Se !near && expanded → forçar "Olha" com nota de distância
// Se !expanded → "Pula" (fora do raio)
```
