## Story

**As a** equipe da ENIAC (Aline admin + Alice + Giovanna + 1 outro),
**I want** um banco de dados de habilitação compartilhado (vault) onde todos podem ver e editar certidões, balanços, atestados e modelos de proposta de um workspace único,
**so that** o Noyce consiga gerar o workflow completo (proposta, planilha, declarações) conectado a documentos reais e atualizados, e cada membro da equipe acesse com seu login (Aline com permissões de admin) sem precisar sessões separadas.

## Contexto

**P0 — Esta story é o desbloqueador do workflow completo.** Declarado pelo founder em reunião 15/Jun/2026 (doc 29 §9): "Pendência única do founder: montar o banco de dados + tornar operacional (conectar) → 'aí faz tudo perfeitamente'. ETA: máx. 2-3 dias."

Requisitos combinados da reunião 15/Jun (doc 29 §3 + §8):
- **Vault de habilitação** (§3): certidões com validade mensal/anual, balanços, atestados/CATs, modelos de proposta em papel timbrado, dados de empresas parceiras de consórcio.
- **Multiusuário** (§8): 4 logins, workspace compartilhado (não sessões individuais), Aline = admin, views por papel (Alice → proposta/planilha/análise final; Giovanna → busca/documentação).

O `noyce-vault.ts` atual é **client-side only** (IndexedDB do navegador). Esta story migra o vault para **persistência compartilhada** acessível por todos os 4 usuários.

[AUTO-DECISION] Backend para o vault compartilhado: Supabase (Postgres + Auth) vs arquivo JSON em servidor vs outro? → **Supabase** — já é o padrão do ecossistema AIOS (vide `anipis`, `serenity-ai`). Fornece: Auth com JWT, RLS por organização, Storage para blobs de certidões, Postgres para metadados. Razão: time-to-market (2-3 dias), sem ops overhead, RLS isola a ENIAC de futuros clientes. Verificar se o projeto Noyce já tem um projeto Supabase ou criar novo.

[AUTO-DECISION] Os 4 logins são criados como usuários Supabase Auth ou auth própria? → Supabase Auth (email + senha). Razão: alinhamento com o ecossistema já usado, suporte a RLS nativo, sem implementar auth do zero. Aline é criada com role `admin` via `user_metadata.role = "admin"`.

[AUTO-DECISION] Views por papel: implementar como rotas diferentes ou como componentes condicionais? → Componentes condicionais guiados pelo papel do usuário logado (não rotas separadas). Razão: o workspace é compartilhado — Aline pode ver tudo; a UI apenas prioriza e destaca as funcionalidades do papel. Rotas separadas fragmentariam o fluxo colaborativo.

[AUTO-DECISION] Segurança de arquivos sensíveis (LGPD, doc 26 §9 invariante 4): certidões e balanços são documentos pessoais/empresariais. → Armazenar blobs no **Supabase Storage** com bucket privado (acesso somente via signed URL com TTL curto). Metadados (tipo, validade, status) ficam no Postgres. Nunca expor URL direta de arquivo. Razão: invariante crítica do projeto "credenciais/arquivos sensíveis só no vault, nunca em doc/JSON/git/print."

## Acceptance Criteria

### Autenticação e Acesso

1. **Dado** que Aline (admin) acessa o Noyce pela primeira vez com as credenciais fornecidas pelo founder,
   **Quando** realiza login com email + senha via Supabase Auth,
   **Então** é autenticada com sucesso e vê o workspace completo da ENIAC com indicação "Admin".

2. **Dado** que Alice ou Giovanna (usuários normais) acessam o Noyce,
   **Quando** realizam login com suas credenciais,
   **Então** são autenticadas e veem o mesmo workspace compartilhado (mesmos documentos, mesmas licitações monitoradas) que Aline vê.

3. **Dado** que um usuário não autenticado tenta acessar qualquer rota do Noyce,
   **Quando** a página carrega,
   **Então** é redirecionado para a tela de login (middleware de autenticação).

4. **Dado** que Aline (admin) está logada,
   **Quando** acessa a seção de administração do vault,
   **Então** consegue adicionar/editar/remover documentos e gerenciar os 4 usuários da organização.

5. **Dado** que Alice (usuária normal) está logada,
   **Quando** tenta acessar funcionalidades de administração (ex.: gerenciar usuários),
   **Então** recebe mensagem "Acesso restrito — apenas administradores" e não vê as opções de admin.

### Vault de Documentos

6. **Dado** que Giovanna está logada e acessa o Vault,
   **Quando** faz upload de uma CND Municipal com validade informada,
   **Então** o documento fica disponível para todos os 4 usuários da ENIAC (workspace compartilhado) com status "OK" e a validade exibida.

7. **Dado** que um documento do vault tem validade expirada (data atual > `validUntil`),
   **Quando** qualquer usuário visualiza o vault ou o checklist de habilitação,
   **Então** o documento aparece com status "Expirado" em vermelho e nota de urgência de renovação.

8. **Dado** que um documento tem validade próxima do vencimento (≤ 30 dias),
   **Quando** o usuário visualiza o vault,
   **Então** aparece alerta amarelo "Vence em X dias — renovar."

9. **Dado** que Giovanna faz upload de um CAT/Atestado no vault,
   **Quando** o arquivo é salvo,
   **Então** o blob fica no Supabase Storage (bucket privado) e os metadados (tipo, RT associado, serviço canônico, quantitativos) ficam no Postgres, acessíveis por todos da organização.

10. **Dado** que o vault tem certidões e balanços carregados,
    **Quando** o motor de habilitação (`buildHabilitationResult`) é chamado para um edital,
    **Então** ele consulta os documentos REAIS do vault (não fixtures hardcoded) para preencher o `CompanyCapabilityProfile` e o `RegularityDoc[]`.

### Empresas Parceiras de Consórcio

11. **Dado** que Aline acessa a seção "Empresas Parceiras" do vault,
    **Quando** cadastra uma empresa parceira (razão social, CNPJ, porte, acervo básico),
    **Então** a parceira fica disponível para seleção no toggle de consórcio (Story 30.2 AC: 3).

### Views por Papel

12. **Dado** que Alice está logada,
    **Quando** visualiza a tela principal do Noyce,
    **Então** a navegação destaca as abas "Analisar" e "Habilitar" (foco proposta/análise final), e o painel de atalhos mostra "Documentos pendentes de revisão" como primeira prioridade.

13. **Dado** que Giovanna está logada,
    **Quando** visualiza a tela principal,
    **Então** a navegação destaca as abas "Mesa" e "Monitorar" (foco busca/documentação), e o painel de atalhos mostra "Licitações novas descobertas" como primeira prioridade.

### Isolamento e Segurança

14. **Dado** que um futuro segundo cliente (organização B) for adicionado ao sistema,
    **Quando** qualquer usuário da ENIAC (organização A) consulta o vault ou as licitações,
    **Então** vê APENAS os dados da organização A (RLS por `org_id` no Postgres garante isolamento).

15. **Dado** que um arquivo de certidão é solicitado para download,
    **Quando** o sistema gera o link de acesso,
    **Então** é uma signed URL do Supabase Storage com TTL de no máximo 15 minutos (nunca URL pública permanente).

### Schema Postgres (Supabase)

```sql
-- Organizações
create table organizations (
  id text primary key,           -- ex: "eniac"
  name text not null,
  cnpj text,
  created_at timestamptz default now()
);

-- Usuários (via Supabase Auth user_metadata)
-- role: "admin" | "user"
-- org_id: referência à organização

-- Documentos do vault
create table vault_docs (
  id uuid primary key default gen_random_uuid(),
  org_id text not null references organizations(id),
  doc_type text not null,        -- VaultDocType do noyce-vault.ts
  label text not null,
  storage_path text,             -- path no Supabase Storage (bucket privado)
  valid_until date,
  status text,                   -- ok | expirando | expirado
  metadata jsonb,                -- quantitativos, RT associado, etc.
  created_by uuid,               -- auth.uid()
  created_at timestamptz default now()
);
alter table vault_docs enable row level security;
create policy "org_isolation" on vault_docs
  using (org_id = (auth.jwt() -> 'user_metadata' ->> 'org_id'));

-- Empresas parceiras de consórcio
create table partner_profiles (
  id uuid primary key default gen_random_uuid(),
  org_id text not null references organizations(id),
  razao_social text not null,
  cnpj text,
  porte text,                    -- ME | EPP | medio | grande
  acervo_basico jsonb,           -- resumo de serviços da parceira
  created_at timestamptz default now()
);
alter table partner_profiles enable row level security;
create policy "org_isolation" on partner_profiles
  using (org_id = (auth.jwt() -> 'user_metadata' ->> 'org_id'));
```
