02 · Cada Estágio Por Dentro

Como funciona passo a passo — sem caixa-preta.

Para cada estágio: o que faz, fluxo técnico numerado, exemplo prático, tempo economizado, e os 2 ou 3 riscos principais com mitigação. Cada cor abaixo identifica um estágio.

01
Radar · 24/7 · WhatsApp

Monitorar

Sistema vigia 3 portais públicos a cada 15 minutos. Match WhatsApp em segundos.

< 15min do publish ao push

O que faz

A cada 15 minutos, consulta PNCP + e-Compras DF + Águas Lindas, filtra editais novos por CNAE/valor/palavra-chave e calcula um match score 0-100 cruzando com seu perfil. Acima do threshold, push WhatsApp.

  • Cobertura: 3 portais oficiais + DODF como fallback RSS
  • Filtros: CNAE primário/secundário, faixa de valor, palavras-chave
  • Dedup por hash (órgão + número + ano) — nunca duplica push
  • Templates HSM aprovados Meta — zero risco de ban WhatsApp
Exemplo prático

10:42 — Águas Lindas publica edital "mobiliário hospitalar R$180k". 10:48 — seu WhatsApp toca: "Novo edital · match 87% · prazo 25/Mai". Você abre, decide, segue.

Fluxo técnico
1Inngest cron dispara monitorar.tick a cada 900s
2Worker consulta 4 fontes em paralelo: PNCP REST, e-Compras DF, Portal Águas Lindas (Playwright), DODF (RSS)
3Normaliza cada edital novo no schema canônico licitacao (Postgres) — dedup por hash
4Computa match_score: CNAE (0.4) + valor (0.3) + cosine similarity objeto via Legal-BERTimbau (0.3)
5Se score ≥ 0.65, dispara whatsapp.send com template HSM edital_novo_v1
6Cliente recebe push em < 15min da publicação no portal
02
MOAT · Análise Histórica · 6 Meses

Analisar 6 Meses

Antes de você decidir, o sistema já leu 6 meses de contratos do mesmo órgão. 4 padrões prescritivos extraídos.

< 90s por edital (cache quente)

O que faz

Para cada edital marcado de interesse, consulta todos os contratos aprovados daquele órgão nos últimos 6 meses e extrai 4 padrões objetivos com fonte citada (contrato N, página X).

  • Vencedores recorrentes: CNPJs que ganham 80%+ das licitações similares
  • Preço médio aceito: faixa P25-P75 por objeto similar
  • Requisitos não-óbvios: ACT/certs comuns além do exigido literalmente
  • Motivos de derrota: por que outras propostas foram desclassificadas
Por que isso é MOAT

Effecti/ConLicitação fazem análise histórica desde 2024, mas entregam lista bruta. Você entrega 4 padrões prescritivos com fonte citada. Para concorrente copiar: retreinar pipeline + reescrever UX = 6-12 meses.

Fluxo técnico
1UI dispara POST /api/workflow/interesse/{id} → Inngest event analisar.run
2Worker query Postgres por contratos do órgão últimos 6m. Se cache vazio, enrich via PNCP /atas/{orgao}
3Legal-BERTimbau-large-v2 (1024d MIT) gera embedding do objeto + busca top-N similares via pgvector HNSW
4LLM judge (Claude Haiku / GPT-5.1-mini) extrai os 4 padrões com source citation obrigatória
5Validação: cada padrão tem source válido? Se não → retry 1×, depois fallback descritivo
6Push WhatsApp: "Análise pronta — 4 padrões extraídos. Abrir →"
03
MOAT · Síntese Prescritiva

Indicar Diferencial

Com base na análise, sistema te diz o ângulo certo para ganhar este edital específico — em 5 frases.

60s leitura no celular

O que faz

LLM forte (GPT-5 / Claude Sonnet) combina padrões do Estágio 02 + seu vault de ACTs + sua margem-padrão → gera 5 frases acionáveis. Não é receita pronta, é o ângulo certo pra você decidir.

  • Faixa de preço aceita pelo órgão historicamente
  • Certificação/ACT que aumenta sua chance específica
  • Concorrente provável + ponto fraco identificável
  • Risco principal (motivo mais comum de derrota)
  • Tempo certo de submeter (padrão observado)
Exemplo de saída · Edital DF-2026-1234

• Preço: vencedores cobraram R$160-195k. Sua margem comporta R$172k confortável.
• Diferencial: 83% dos vencedores ofereceram garantia 24m. Você não oferece.
• Concorrência: 3 CNPJs dominam. Empresa Y teve CRF vencido 2× — vulnerável.
• Risco: 41% das derrotas foram por ACT objeto incompatível.

Fluxo técnico
1Auto-disparado: Inngest event diferencial.synthesize quando analise_orgao.status = pronto
2Worker carrega contexto: 4 padrões + empresa.vault_acts + empresa.margem_minima_pct + certificações
3Constrói prompt para LLM forte com instrução: "5 frases acionáveis, cite fonte de cada uma"
4LLM retorna JSON estruturado com source IDs. Validação: cada source existe no DB? Sim/não
5Se qualquer source inválida → retry 1× com prompt estrito. Falhar → bloqueia e mostra Estágio 02 cru
6Push WhatsApp + cartão visual no app: "Diferencial pronto · 5 pontos · 60s leitura"
04
Execução · Dossiê Production-Grade

Habilitar

De 4 horas refazendo dossiê manual para 28 minutos revisando PDF compilado.

4h → 28min −85% do trabalho manual

O que faz

Sistema cruza cada exigência do edital com seu vault de certidões/ACTs/BP-DRE, alerta o que falta, renova CRF FGTS via API Caixa, e compila o PDF unificado em 60 segundos.

  • CRF FGTS · CND Fed/Est/Mun · CNDT · CNDP — monitoradas o ano todo
  • BP/DRE + índices LG/LC/SG gerados do livro caixa automaticamente
  • ACT matcher pontua 0-10 cada par (vault, exigência) com fórmula TCU-defensável
  • pdf-lib (MIT) costura PDF final na ordem do edital com bookmarks
Tempo poupado −3.5h/edital × 5-30 editais/mês
Receita preservada R$ 5-50k por inabilitação evitada
Fluxo técnico
1API recebe POST /api/workflow/habilitar/{id} → Inngest event habilitar.compile
2Worker baixa anexos do edital (PDFs) e salva em Supabase Storage
3Docling (IBM, MIT) faz parse com TableFormer; fallback Mistral OCR 3 se confidence <0.7
4Cruzamento paralelo: certidões (vault) + BP/DRE (livro caixa) + ACTs (LLM judge)
51-click renew CRF FGTS via API Caixa quando vencendo <7d
6pdf-lib costura tudo + você revisa 14min + envia. Total: 28min do clique
05
Execução · SLA Crítico · Preclusão

Acompanhar Sessão

No momento que vencedor é declarado, sistema baixa documentos e roda 4 verificações em <3min.

< 3min para decidir recurso

O que faz

Sistema monitora a sessão pública em tempo real. Quando alguém é declarado vencedor, baixa documentos e roda 4 verificações automáticas classificando achados em INSANÁVEL / DUVIDOSO / SEM BRECHA.

  • CRF FGTS vencedor está válido? (consulta Caixa em tempo real)
  • CND Federal está válida? (consulta RFB direto)
  • Sócios em CEIS / CNJ Improbidade? (Portal da Transparência)
  • ACT objeto compatível? (match semântico contra exigência)
Push WhatsApp · 18:00

Vencedor declarado: Empresa Y CNPJ XX/XXX-XX
⚠ INSANÁVEL — CRF FGTS expirou em 16/Mai
⚠ INSANÁVEL — sócio em CEIS
⚠ DUVIDOSO — ACT 'mobiliário escolar' vs edital hospitalar
Score recurso: 9.2/10 · recomendação forte

Fluxo técnico
1Inngest acompanhar.poll ativo durante janela sessão (start ± 4h), polling 30s
2Quando PNCP retorna status vencedor_declarado, captura cnpj + valor + documentos
34 verificações em paralelo — Caixa CRF, RFB CND, Portal Transparência CEIS, LLM ACT match
4Classifica achados: INSANÁVEL (CRF, CEIS) · DUVIDOSO (ACT) · SEM BRECHA
5Calcula score_recurso 0-10: ≥8 = recomendação forte; 4-7 = decisão tática; <4 = não recorrer
6Push WhatsApp com relatório anexo — total: <3min do "vencedor declarado"
06
Execução · RAG Jurídico · Anti-Preclusão

Recorrer

Se score_recurso >5, sistema gera minuta com fundamento legal validado em <30 segundos.

< 8min do achado ao envio

O que faz

RAG jurídico busca fundamento legal preciso em corpus indexado (Lei 14.133, Súmulas TCU, Acórdãos chave), aplica template validado por advogado, e gera minuta auditável. Cita base legal real — não inventa.

  • Corpus indexado: Lei 14.133/2021 full text + ~200 súmulas TCU + ~50 acórdãos chave
  • Validação obrigatória: cada citação legal verificada contra corpus antes do output
  • Princípio Justen Filho: "fundamento referenciado, não inventado"
  • Sistema agenda automaticamente "razões finais em 3 dias úteis"
Dentro do prazo 100% zero perda por preclusão
Receita reaverta R$ 5-50k por recurso procedente
Fluxo técnico
1Inngest event recorrer.draft disparado se score_recurso > 5 + você confirmou
2RAG jurídico: vector search no corpus indexado, recupera 2-3 fundamentos por achado
3LLM forte aplica template advogado-validado, preenche com fatos concretos + base legal
4Validação obrigatória: cada citação existe no corpus? Súmula é vinculante? Se não → bloqueia
5PDF gerado via pdf-lib + assinatura digital opcional (ICP-Brasil A1)
6Push WhatsApp + agenda task automática: "razões finais em 3 dias úteis"

Fundação · Backstage Integration · MOAT estrutural

Base · Livro Caixa 3 Empresas

Open Finance importa transações. IA categoriza. Família aprova com 1 tap. BP/DRE fica sempre vivo.

< 10s por lançamento

O que faz

App PWA no celular onde a família lança receita/despesa das 3 empresas. Pluggy Open Finance importa transações bancárias automático. IA sugere categoria contábil. Auto-BP/DRE alimenta o Estágio 04 sem contador no caminho.

  • RBAC granular: cada pessoa só vê a empresa dela (Postgres RLS)
  • Pluggy (R$48/mês) cobre 90%+ bancos PJ BR — sandbox grátis para dev
  • Plano de contas ITG 1000 (CFC) — aceito por contadores e TCU
  • Cálculo automático LG/LC/SG (índices Lei 14.133 art. 69) com fallback art.69 §3º
Dia típico · tarde

14:55 Push: "8 transações novas em Empresa A, aguardando aprovação"
14:56 Pessoa abre app, vê 8 cards com categoria sugerida
14:57 "Boleto Fornecedor X · R$1.500" → tap OK
14:59 Tudo classificado em <3min · BP/DRE da licitante fica sempre vivo

Schema multi-tenant (8 tabelas core)
1empresa — 3 rows (1 licitante + 2 gestão), com parent_group_id para Lei 14.133 art. 14 IV
2usuario + role — RBAC granular: master / receita / despesa / leitor
3plano_contas — seed ITG 1000 versionado (não editável Fase 1)
4transacao — origem manual / pluggy / ocr_nota · status pendente/aprovada
5conexao_bancaria — Pluggy item_id, last_sync, status
6audit — LGPD: cada view/edit/export/delete logado com IP + user + recurso
03 · Stack Técnica

Cada escolha justificada.

Tudo aberto e auditável. Nenhuma escolha por modinha — cada ferramenta tem licença compatível com produto comercial, custo Fase 1 mapeado, e fallback definido.

[ Frontend ] Next.js 16 RSC + Server Actions. Deploy Vercel 1-click. Stack conhecida. R$ 0 (Hobby)
[ Banco ] Supabase Postgres 15 + pgvector + RLS + Auth + Storage no mesmo SDK. R$ 130/mês Pro
[ Jobs ] Inngest Event-driven, retry automático, dashboard nativo. Não polling. R$ 0 → R$ 100
[ Vector ] pgvector HNSW <20k vetores. Não introduzir Qdrant/Pinecone. Mantém 1 DB. R$ 0 (incluído)
[ PDF Parse ] Docling (IBM) MIT. TableFormer melhor OSS p/ tabelas. NÃO Marker (GPL-3). R$ 0 (compute)
[ OCR Fallback ] Mistral OCR 3 $1-2/1000pg. Top em escaneado. Só chamado se Docling falhar. R$ 10-30/mês
[ Embeddings ] Legal-BERTimbau-large-v2 MIT. State-of-art PT-BR jurídico. Self-host 512MB RAM. R$ 0 (compute)
[ LLM Judge ] Claude Haiku ~R$0.05/judgment. Latência <3s. Eval contínuo. <R$ 30/mês
[ LLM Forte ] Claude Sonnet Estágio 3 síntese prescritiva. 1× por edital. Caro mas vale. <R$ 50/mês
[ Open Finance ] Pluggy 90%+ bancos BR PJ. BACEN direto requer ICP+DCR (não vale). R$ 48/mês (3 CNPJs)
[ WhatsApp ] Cloud API Meta Único path defensável. Baileys/Wppconnect = risco ban. ~R$ 50/mês
[ Scraping ] Playwright Apenas para Águas Lindas (PCP privado). DF/PNCP = API REST. R$ 0 (compute)

08 · Como Defender Em Call

5 perguntas que vão aparecer.

Cada uma já tem resposta pronta com source. Treine essas antes da call — são as objeções que cliente faz quando começa a entender o produto de verdade.

Isso é IA? Não vai alucinar?
Toda saída tem source citation obrigatória. Se o sistema não consegue citar fonte (contrato N, página X), ele não entrega — pede revisão humana. Princípio canalizado de Justen Filho: "citação legal deve ser referenciada, não inventada". Está hardcoded na validação de saída do Estágio 3 e Estágio 6.
Como você sabe que isso vai funcionar antes de construir?
3 gates objetivos: F1 do ACT matcher ≥ 0.75 (Sprint 4), parsing_confidence ≥ 0.7 em 80% editais (Sprint 4), 1 edital ganho via diferencial (Sprint 6). Se qualquer gate falhar, pivot ou kill. Não vou queimar 22 semanas se Sprint 4 mostrar que não funciona.
E LGPD? Vou processar dados sensíveis das 3 empresas.
Dados nunca saem do Brasil. Embeddings rodam self-host (Legal-BERTimbau MIT). LLM externo recebe só objeto do edital + estatísticas agregadas — nunca CNPJ ou ACT bruto. RLS Postgres isola cada empresa. Audit log de cada acesso (Art. 18 LGPD). DPA com Pluggy, Anthropic, Meta antes da assinatura.
Por que não pago Effecti? É mais barato.
Effecti te dá alerta + lista bruta. Não te diz como ganhar o edital específico. Você gasta 4h refazendo dossiê manual. Effecti não integra com seu livro caixa. Custo manual escondido = ~R$ 415k/ano (tempo + 1-3 inabilitações/ano evitáveis). R$ 2.800/mês = ROI 12×. Conta fechada.
E se você desistir do projeto?
Esse é o ponto do workflow-as-a-service — você não fica refém. Cada dado seu vive no Supabase, exportável a qualquer momento em formatos abertos (CSV, JSON, OCDS). Banco de ACTs, vault, plano de contas, livro caixa: tudo seu. Migração pra outra solução é trivial. Não vendo lock-in, vendo workflow.
