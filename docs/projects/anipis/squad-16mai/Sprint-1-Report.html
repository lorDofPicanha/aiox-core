P0 #14 — Art. 18 Saga (entregável central Sprint 1)

A peça mais ambiciosa do sprint: implementação completa do LGPD Art. 18 Direito ao Esquecimento conforme spec de Lucia Savage. Cobre 17 tabelas, com lógica diferenciada por tipo de PII, e wireado end-to-end (DB → cache Redis → Supabase auth → audit trail).

Saga em 19 steps

Pre-flight:
  - pg_advisory_xact_lock(hashtext(userId))    ← race-condition guard
  - assertSafeToDelete()                       ← crisis guard (Art. 11,II,"f")

TX (FK-aware order):
  1.  DELETE messages
  2.  DELETE journal_entries                   ← novo
  3.  DELETE conversations
  4.  DELETE mood_checkins
  5.  DELETE emergency_contacts
  6.  DELETE exercises
  7.  DELETE assessment_results
  8.  DELETE beta_feedback
  9.  DELETE nps_responses
  10. DELETE dependency_tracking               ← novo
  11. DELETE professional_ai_configs WHERE patient_id=userId    ← novo
  12. DELETE professional_patient_links WHERE patient_id=userId ← novo
  13. INSERT tombstone profile (ON CONFLICT DO NOTHING)
  14. UPDATE crisis_events SET user_id=tombstone,
             classifier_output.matchedKeywords=[]   ← PII strip
  15. UPDATE consents SET user_id=tombstone,
             ip=NULL, ua=NULL, revoked_at=NOW
  16. UPDATE granular_consents (idem)
  17. UPDATE audit_events SET user_id=tombstone  ← hash chain preservada
  18. UPDATE deletion_requests SET user_id=tombstone
  19. DELETE profiles WHERE id=userId

Post-TX:
  - auditTrail.scanAndReplaceUserId(userId, tombstoneId)   ← buffer rewrite
  - audit emit: deletion_hard_completed (tombstoneId)
  - purgeUserCache(userId, redis)                          ← 7 Upstash patterns
  - supabase.auth.admin.deleteUser(userId)                 ← Supabase auth purge
  - audit emit: auth_user_purged
Key design decision

HARD DELETE vs PSEUDO — 13 tabelas com PII direta vão pra DELETE. 5 tabelas com função de comprovação legal (crisis_events, consents, granular_consents, audit_events, deletion_requests) vão pra PSEUDO (user_id → sha256(userId) tombstone). Hash chain do audit_events permanece íntegra porque current_hash NÃO é recomputada — tombstone é semanticamente equivalente pro chain.

Lições aprendidas

1. vitest alias diretório → Vite prefere .js sobre .ts

Root cause do "stale .js" bloqueava P0 #13 inteiro. Fix definitivo: purgar artefatos build no packages/shared/src/. Repo apps/* gitignored ajudou (sem rollback risk). Lição: aliases apontando pra diretório seguem ordem padrão de extensão do bundler — preferir apontar pro arquivo .ts explícito OU manter src/ limpo de artefatos.

2. Helper functions classifier testavam pattern.source ao invés de input

hasCriticalPsy, hasSevereSleep, hasCriticalED, hasNostalgia faziam regex contra pattern.source (uma string com sintaxe regex). A sintaxe bloqueava o match. Spec Lucia tinha placeholder /*...*/ indicando que deveria testar input. ~1h de debugging recuperada.

3. Bug pré-existente revelado pela mudança PSEUDO

Old code fazia DELETE deletion_requests no executeHardDelete, e processPendingDeletions tentava UPDATE status='completed' depois — silenciosamente 0 rows. Spec PSEUDO (UPDATE→tombstone) resolveu pelo lado da arquitetura.

4. DI > singleton em serviços com side-effects externos

AccountDeletionService aceita postDeleteHook + auditTrail via constructor. Tests passam stubs zero-config. Produção wires no route handler com Supabase admin + Redis + AuditTrail. Mesma arquitetura escala se Anipis adicionar Stripe/Twilio/SendGrid futuramente.

5. Spec items numerados são entregáveis, não bonus

Inicialmente rotulei "CI gate Art.18" como "Defensive engineering futuro" — o founder corrigiu: era item 18 explícito da spec Lucia. Boa lição operacional: spec items com número são deliverables, não opcional. "Não é defensive engineering, é completude do P0."
