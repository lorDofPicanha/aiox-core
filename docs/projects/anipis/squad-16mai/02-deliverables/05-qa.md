## 4. Eval Harness Design

**Objetivo:** garantir que safety score é **mensurável, reproduzível e regredável** a cada PR/troca de modelo.

### 4.1. Golden set 200+

- **Composição:** 60 crisis (15 cenários × 4 variantes), 40 routine, 30 ambiguous, 30 jailbreak, 25 PII/LGPD, 15 multi-turn drift.
- **Formato:** JSONL `{id, scenario, turns:[…], expected_signals:[crisis_routing, refusal, handoff], expected_phrases:[…], forbidden_phrases:[…]}`.
- **Localização:** `apps/serenity-ai/tests/eval/golden-set/` (gitignored a partir do conteúdo sensível; metadata versionado).
- **Anotação:** mínimo 2 anotadores (1 psicólogo, 1 QA), inter-rater κ ≥ 0.7.

### 4.2. Automated regression

- **Runner:** custom `eval-runner.ts` que chama `/chat` em staging com sessões isoladas (`X-Eval-Run-Id`).
- **Métricas:** TPR crisis, FPR crisis, jailbreak resistance, hallucination rate (claim médico inverificável), latency p50/p95, refusal rate.
- **Storage:** Langfuse traces taggeadas + dump CSV em `reports/eval/{date}-{model}.csv`.
- **CI gate:** GitHub Action em PR que toca `services/llm/**`, `safety/**`, `prompts/**`. Roda subset 50 cenários (fast). PR bloqueia se TPR cai > 2% ou FPR sobe > 3% vs baseline.

### 4.3. Weekly full run

- Cron semanal (segunda 06:00 BRT) roda 200 completo em staging.
- Resultados publicados em dashboard Langfuse + Slack `#anipis-qa`.
- **Alert:** se safety score < baseline - 5% por 2 runs consecutivos → pausa rollout automático + page on-call.

### 4.4. Adversarial expansion

- Quinzenal: 2h de red-team manual livre + 20 cenários novos adicionados ao golden set.
- Trimestral: pentest externo (firm com expertise saúde digital, ex: Trail of Bits / Cure53).

## 7. Audit Log Requirements

**Princípios:** append-only, integridade verificável, retenção LGPD, anonimização pré-API.

### 7.1. Schema mínimo

```sql
CREATE TABLE audit_log (
  id BIGSERIAL PRIMARY KEY,
  ts TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  actor_id UUID,           -- FK profiles (anonimizável)
  actor_role TEXT,         -- patient|professional|admin|system
  action TEXT NOT NULL,    -- ex: 'professional.view_conversation'
  resource_type TEXT,
  resource_id UUID,
  ip_addr INET,
  user_agent TEXT,
  payload JSONB,           -- diff/contexto, PII scrubbed
  prev_hash BYTEA NOT NULL,
  curr_hash BYTEA NOT NULL -- SHA-256(prev_hash || row_json)
);
CREATE INDEX ON audit_log (actor_id, ts DESC);
-- INSERT trigger calcula curr_hash; UPDATE/DELETE proibidos via RLS + grant.
```

### 7.2. Cryptographic hash chain

- Cada row referencia hash da anterior (`prev_hash`). Quebra detectável.
- Verificação semanal via cron `verify-audit-chain.ts` (alarme se quebrar).

### 7.3. Retention

- **Audit log:** 5 anos (CFP/LGPD para dados de saúde derivados).
- **Consents (`granular_consents`):** 5 anos pós-revogação.
- **Crisis events:** 5 anos (legal proteção em caso de incidente).
- **Conversas/mensagens:** soft-delete 30d + hard-delete + anonimização derivada.

### 7.4. Anonimização pré-API

- LLM nunca recebe `userId` cru. Hash por sessão (`session_id = sha256(userId||conversation_id||salt_dia)`).
- Logs Langfuse: PII scrubbed via NER PT-BR (nomes, CPF, telefone, endereço, email) antes de persistir.
- Profissional vê PII (necessário clínico), LLM não.

### 7.5. DPO access

- Endpoint `/dpo/audit-query` protegido por `dpo` role + MFA + auditado meta-auditoria (acesso DPO também loga).
- DPO pode exportar trail por usuário sob solicitação Art. 18 (export em até 15 dias).
