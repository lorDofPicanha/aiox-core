SOLID no Build

SOLID foi incorporado como gate de construcao, nao como licenca para abstracao generica. Cada decisao deve proteger uma fronteira real.

Principio Aplicacao em F1-D0
Single Responsibility DB, motor, verifier e fitness ficam em pacotes separados, cada um com uma razao clara para mudar.
Open/Closed Regras e versoes evoluem por dados: base_versao, motor_versao, golden_set_versao.
Liskov Adapters futuros preservam fila in, candidatos out e RPC materializadora.
Interface Segregation core_api_v1 expoe uma API pequena; consumidores nao acessam tabelas internas.
Dependency Inversion UI, provider, RAG e Gestorize dependem do core publicado; o core nao depende deles.

Riscos e Alertas

Risco Impacto Mitigacao
docs/stories/ ignorado no Git A story existe localmente, mas nao entra em commit por padrao. Decidir entre git add -f, mover/copy para docs do projeto, ou manter local.
Worktree sujo Build pode misturar mudancas nao relacionadas. Checkpointar docs do Contador ou isolar explicitamente o escopo antes de codar.
Golden-set sintetico Pode ser confundido com acuracia fiscal real. Marcar como teste sintetico; ground-truth real depende de tributarista rotulador.
security definer em RPC Pode abrir bypass se grants/RLS forem mal desenhados. Testes negativos obrigatorios de grants, RLS e escrita direta.
